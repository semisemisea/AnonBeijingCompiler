# soyo_compiler：前端设计文档

本文档对应编译系统实现赛道的前端部分，说明词法、语法分析、AST 设计、到 RaanaIR 的下降，以及大模型使用情况。优化与后端设计见 `anon.md`、`uika.md` 与工程内对应文档。

## 一、定位与整体流水线

前端由 `soyo_compiler` crate 承担，包含命令行入口、词法与语法分析、AST 定义与到 RaanaIR 的下降。编译流水线：

```
SysY2026 源码 → lalrpop 词法/语法分析 → AST → RaanaIR（SSA HLIR）→ IR 优化 → 后端汇编
```

前端输出是 `raana_ir::ir::Program`。两个后端与全部 IR 优化 pass 都运行在这份 IR 上，因此前端与目标平台无关，相同的 AST 下降结果供 AArch64 与 RISC-V 后端复用。

## 二、命令行与调用约定

可执行文件名为 `compiler`，按技术方案的调用形式工作：功能测试 `compiler testcase.sysy -S -o testcase.s`，性能测试附加 `-O1`。参数用 clap 解析。

- `-S` 等价于 `--emit asm`。`--emit ir,asm` 可同时输出多种产物，此时 `-o` 指向输出目录，文件名取自输入文件名。
- `-O 0..=2` 选择优化级别，默认 2。级别同时决定 IR pass 集合与后端 MIR pass 集合。
- `--target aarch64|riscv64`，默认 aarch64。IR 优化按目标选择 pass 集合。
- 后端 pass 有独立的 `--enable/--disable-*` 开关覆盖级别默认值；RISC-V 目标下 AArch64 专属开关被拒绝。
- `--pass-stats` 把 IR pass 的统计输出到 stderr，`--loop-unroll on|off|dry-run` 覆盖循环展开模式。

入口在 `main.rs`：读源码、解析、下降、跑 IR pass，再按目标选择后端生成汇编。

## 三、模块划分

| 模块 | 职责 |
|------|------|
| `cli.rs` | 命令行参数解析、优化配置构造、参数校验 |
| `sysy.lalrpop` | 词法规则与 SysY2026 文法，构建期由 lalrpop 生成解析器 |
| `frontend/items.rs` | AST 结构定义与数组初始化形状计算 |
| `frontend/ast.rs` | AST 到 RaanaIR 的下降实现（`ToRaanaIR`） |
| `frontend/utils.rs` | `AstGenContext`：符号表、值栈、基本块与 IR 构造接口 |
| `abi_matrix.rs` | 跨 target ABI 回归矩阵（测试） |

## 四、词法与语法分析

词法与语法都写在 `sysy.lalrpop` 一个文件里，改文法只需改这一处。

- 词法规则写在文法的 match 块中：空白、`//` 行注释与 `/* */` 块注释直接跳过，标识符、整数、浮点数用正则匹配。
- 整数常量支持十进制、八进制（`0` 前缀）与十六进制（`0x` 前缀）。
- 浮点常量支持十进制小数、科学计数法与 C99 十六进制浮点，解析用 C 库的 `strtof`，保证与 C 语义一致。
- 文法覆盖全局声明、函数定义、语句与表达式。悬挂 else 通过 MatchedStmt 与 OpenStmt 两个规则消除歧义，使 `else` 就近绑定。
- 数组参数支持 `int a[]` 与 `int a[][N]` 两种形式，下降时成为指针。

语法错误由 lalrpop 的 `ParseError` 报告，携带行列信息，经入口的 `unwrap` 以 panic 消息输出。

## 五、AST 设计

`items.rs` 用嵌套枚举表示表达式，层次与 C 的优先级一一对应：

```
Exp → LOrExp → LAndExp → EqExp → RelExp → AddExp → MulExp → UnaryExp → PrimaryExp
```

每一层只有叶子与组合两种形态，组合把左操作数、运算符与右操作数装进结构，左结合由树形本身表达，下降时不需要运算符优先级表。表达式顺序信息存在树的结构里。语句、声明、初始化与函数定义各对应独立类型，均实现 `ToRaanaIR`。

数组初始化在 AST 层完成形状计算。`init_val_shape` 把嵌套初始化展平为按扁平下标的 `Vec<Option<&Exp>>`，未显式初始化的槽位补零，超出容量的初值截断；`explicit_init_vals` 返回显式给出的 `(下标, 表达式)` 对，局部数组逐元素存储时跳过零槽。空初始化 `{}` 折叠为单一 `ZeroInit`。

## 六、到 RaanaIR 的下降

下降由 `ast.rs` 的 `ToRaanaIR` 实现完成，`utils.rs` 的 `AstGenContext` 提供状态。

- 上下文：持有 `Program`、函数栈、值栈、当前基本块、作用域栈与循环栈。`Program` 由 arena 管理，全局值与局部值分别存放在全局与函数级 arena。
- 符号表：全局作用域在底层，局部作用域进栈，查找从顶向下，同名遮蔽与 C 一致。符号分常量、变量、可调用函数三类。
- 变量：局部标量分配 `alloc` 槽，把槽地址存入符号表；数组局部变量同样 `alloc`，有初始化时先 `mem_zero` 清零再按扁平下标逐元素 store。全局变量用 `global_alloc`，标量直接给初值，数组初值组装成嵌套 aggregate 或 `zero_init`。
- 常量：`const` 声明把常量值存入符号表，使用处直接取常量；对常量赋值在下降时报错。
- 控制流：`if` 生成 then/else/end 三个块，`while` 生成 entry/body/end 三个块；`break` 与 `continue` 查循环栈跳向对应块。基本块以 `br`、`jump`、`ret` 终结，终结后的语句不再下降，未终结的块在切换时自动补默认返回值。
- 短路求值：`&&` 与 `||` 生成两个临时块，按左值真伪分支到求值块或合并块，布尔结果经合并块的块参数传递；两侧都是常量时在下降期折叠，临时块被删除。
- 函数调用：实参按形参类型强制转换，数组实参退化为指向元素的指针。`starttime()`/`stoptime()` 按头文件宏语义改写为 `_sysy_starttime`/`_sysy_stoptime` 调用。输入输出库函数在下降开始时声明（`getint`、`getfloat`、`putint`、`putfloat`、`putf` 等）。
- 编译期常量折叠：二元与一元运算在操作数都是常量时于下降期求值。整数用 `i32` 的 wrapping 语义，与运行时一致；浮点用 `f32`。全局作用域的表达式必须可求值，否则报错。
- 类型转换：`int` 与 `float` 互相赋值或作实参时，双方都是常量则直接改写常量，否则插入 `cast` 指令。

## 七、错误处理

- 语法错误由 lalrpop 报告，含行列信息。
- 语义错误以下降期的 panic 消息说明错误性质，包括未定义变量、重复定义、类型不匹配、对常量赋值、`break`/`continue` 在循环外、把函数当左值。这些消息不携带源码行列。

错误定位目前只到错误性质，不到源码位置。完整的错误恢复与位置报告是已知限制（见第十节）。

## 八、测试

- `items.rs`：C99 浮点常量解析、稀疏数组初始化的扁平位置。
- `abi_matrix.rs`：跨 target ABI 回归矩阵，14 个用例覆盖零到九个参数、整型浮点混合、尾递归、局部数组、参数重赋值等，在双 target 三档优化级别下编译，校验输出逐字节确定。
- 功能用例：前端在 harness 的 `--emit ir` 路径下被整体覆盖，IR dump 崩溃即用例失败。

## 九、借鉴情况

按技术方案第 15 条与第 14 条说明：

- lalrpop 属于赛规明确允许的解析器生成工具。
- 前端早期从团队成员 pku-minic 课程的作业仓库 s2r 迁移，随后为对接 RaanaIR 重写，当前词法、AST 与下降代码是针对 `raana_ir` 的实现。这一来源在仓库 README 与本文档中标注。
- RaanaIR 的设计参考了 KoopaIR 与 LLVM 的中间表示思想，属于 IR 层，不在本文档范围。前端本体不使用 GCC 或 LLVM 的源代码。

## 十、已知限制与后续工作

- 语义错误不带源码位置，只能定位到错误性质。可在下降时记录语句的源码位置并随错误消息输出。
- 错误处理以 panic 结束，缺少恢复能力，无法一次报告多个错误。
- 词法文法尚未覆盖技术方案第 23 条列出的向量类型。IR 层与后端已具备向量支持，前端补齐语法后即可贯通。

## 十一、大模型使用情况

开发过程中使用了大模型辅助工具，说明如下。

- 工具名称：OpenCode（交互式编码代理），以 DeepSeek 系列大模型为推理后端。
- 生成内容范围：部分 Rust 源码（词法文法、AST 与下降代码、单元测试）、代码重构、缺陷修复，以及本文档的撰写。
- 人工修改情况：模型生成的代码经人工逐段审查、改写与集成后再进入工程；正确性以单元测试、功能用例与回归门禁验证。前端未针对任何测例生成或调整代码。

生成代码的可追溯性通过代码注释、单元测试与本文档保证，符合章程第 7.4 条与技术方案第 15 条的要求。
